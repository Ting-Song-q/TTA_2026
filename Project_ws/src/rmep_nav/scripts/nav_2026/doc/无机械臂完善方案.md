## 1. 赛题任务与评分概览

比赛为**空地协同**模式：无人机完成任务一后向智能车发送救援指令，智能车完成取货→装货→救援区卸货→返航。

### 1.1 五个子任务


| 任务            | 执行主体    | 完成标准（摘要）                          | 分值  |
| ------------- | ------- | --------------------------------- | --- |
| 任务一：无人机巡检     | 无人机     | 起飞、记录四救援点等级、发指令给小车、降落装货区          | 70  |
| 任务二：智能车运送物资   | 智能车     | 进取货区、**视觉+抓取**、进装货区               | 50  |
| 任务三：智能车为无人机装货 | 智能车+无人机 | **物资转移到无人机平台**，无人机带离装货区           | 80  |
| 任务四：救援物资投送    | 无人机+智能车 | 无人机送达、小车进救援区、**放入 100×100mm 放置区** | 80  |
| 任务五：返航        | 双方      | 小车回停车区、无人机回停机区                    | 20  |


**碰撞扣分**：车体或加装模块与非任务物体碰撞，每次 **-5 分**。

**超时结束**：设备停止运行超过 **60 秒** 即结束本局，保留已有得分。

### 1.2 任务二、三、四的关键规则原文

- **任务二**：智能车须自主行驶到取货区，**通过视觉识别确定物资位置**，随后**使用加装模块抓取物资**；抓取动作**必须基于视觉识别定位完成，不可预设位置**。
- **任务三**：智能车需将物资放置到无人机搭载平台上，**或以其他形式完成货物从智能车到无人机的转移**，随后通知无人机装货完成。
- **任务四**：无人机将物资运送到救援区并脱离后，智能车须将物资**最终准确放置于指定的目标区域内**（100mm×100mm 物料放置区）。

> **重要**：任务三明确允许"其他形式转移"，不要求必须用机械臂；但任务二要求"抓取"，任务四要求"放入指定区域"，均需要某种**物理取放机构**。

### 1.3 区域到位判定

以下情况均要求：**至少 2 个驱动轮同时位于目标区域内**。

- 取货前（取货区 800×800mm 范围）
- 装货时（装货区）
- 进入救援区
- 返回停车区（800×800mm 停车区）

### 2.3 无机械臂时的抓取模式

`mission_config.yaml` 中：

```yaml
grasp:
  require_hardware: false   # 无机械臂时 false：识别成功即通过
```

当 `require_hardware: false` 且 `ep_arm`/`ep_gripper` 服务不可用时，`vision_grasp()` 在视觉识别+对位成功后直接返回 True，**不会执行真实抓取**。此模式仅适合软件联调，**不能获得比赛抓取得分**。

相关代码逻辑（`nav_rescue_2026.py`）：

```python
if not self._grasp.require_hardware and not self._grasp.hardware_ready:
    rospy.loginfo("vision_grasp detect-only success")
    return True
```

## 4. 现在就能做的软件完善

以下工作**不依赖机械臂**，应优先完成。

### 4.1 标定地图坐标（最高优先级）

**目标**：填写 `mission_config.yaml` 中 `zones` 各点 `(x, y, yaw)`。

**步骤**：

1. 启动导航栈（`move_base` + 地图）
2. 将小车手动遥控到各区域理想停车点
3. 在 RViz 中使用 `2D Pose Estimate` 记录位姿，或通过 `tf_echo map base_link` 读取
4. 分别标定：
  - `parking`：停车区中心，两驱动轮在 800×800mm 内
  - `pickup`：取货区，车头朝向货架，便于摄像头识别
  - `loading`：装货区，便于向无人机平台卸货
  - `rescue.1` ~ `rescue.4`：四个救援区，朝向平台停机区/放置区

**注意**：取货、装货、卸货三处的 `yaw` 角对后续视觉对位和机构动作影响很大，需单独优化。

### 4.2 实现 `assert_wheels_in_zone`

**规则要求**：至少 2 个驱动轮在区域内。

**建议实现思路**：

```python
# 伪代码
WHEEL_OFFSETS = [
    ( wheelbase/2,  track/2),   # 左前
    ( wheelbase/2, -track/2),   # 右前
    (-wheelbase/2,  track/2),   # 左后
    (-wheelbase/2, -track/2),   # 右后
]

def assert_wheels_in_zone(self, zone_name, zone_id=None):
    zone_rect = self._zone_rect(zone_name, zone_id)  # 800x800mm 区域
    wheels_in = 0
    for offset in WHEEL_OFFSETS:
        wx, wy = self._wheel_pos_in_map(offset)  # TF 变换
        if zone_rect.contains(wx, wy):
            wheels_in += 1
    return wheels_in >= 2
```

**参数来源**：从 URDF 或实测获取轮距（track）和轴距（wheelbase）。

**红外辅助**：在区域边缘放置检测逻辑，当 2 个轮子已进区但整车未停准时，用红外测距做最后修正。

### 4.3 视觉识别打磨

**已有能力**（`vision/pickup_detector.py`）：

- HSV 双区间红色检测（适应红色圆柱物资）
- 3×3 货架格子映射，仅识别中心+四边沿格子 `[1,3,4,5,7]`
- 圆度过滤（`min_circularity: 0.45`）
- 支持 YOLO 模式（需训练模型）

**建议调参项**：


| 参数                                    | 文件位置                  | 调参目的      |
| ------------------------------------- | --------------------- | --------- |
| `red_hsv.lower1/upper1/lower2/upper2` | `mission_config.yaml` | 适应赛场光照    |
| `shelf_roi`                           | 同上                    | 裁剪货架有效区域  |
| `min_area`                            | 同上                    | 过滤噪点      |
| `pixel_deadband`                      | `grasp.align`         | 底盘对位精度    |
| `max_iters`                           | `grasp.align`         | 对位迭代次数    |
| `center_offset`                       | `grasp.align`         | 摄像头光心偏移补偿 |


**调试方法**：

- 保持 `save_debug: true`，检查 `/tmp/rescue_vision/` 下图片
- 运行 `test/test_vision.py` 离线验证
- 赛场日光不确定，建议准备两套 HSV 参数（冷光源/强光）

### 4.4 激光避障优化

**已有能力**（`laser_avoidance.py` + `nav_rescue_2026.py`）：

- `move_base_guard`：导航过程中监护，前方被挡则取消 goal 并局部绕障
- `cmd_vel_guard`：直线/转向/视觉对位时修正速度
- `check_proximity_alert`：贴近障碍累计告警（赛后分析用）

**针对 30×30×45cm 障碍物的建议**：


| 参数                        | 当前值  | 建议            |
| ------------------------- | ---- | ------------- |
| `safe_distance`           | 0.30 | 保持，约等于障碍宽度    |
| `emergency_stop_distance` | 0.12 | 可略增至 0.15，更安全 |
| `bypass_speed`            | 0.08 | 保持低速，减少碰撞     |
| `max_bypass_retries`      | 5    | 障碍密集区可增至 8    |


**测试场景**：

- 取货区货架侧面绕行
- 装货区平台转角
- 救援区平台与围栏之间

### 4.5 无人机通信稳定性

**通信协议**（`rescue_protocol.py`）：


| 信号                   | 路径                        | 方向     | 作用                      |
| -------------------- | ------------------------- | ------ | ----------------------- |
| `rescue_cmd.csv`     | `/mnt/rescue_cmd.csv`     | 无人机→小车 | 含 `target_zone`、`level` |
| `loading_done.flag`  | `/mnt/loading_done.flag`  | 小车→无人机 | 装货完成通知                  |
| `delivery_done.flag` | `/mnt/delivery_done.flag` | 无人机→小车 | 投送完成通知                  |


**检查项**：

- `comm.drone_host` / `drone_user` / `drone_password` 与现场网络一致
- 无人机写入 CSV 的字段名与 `wait_for_rescue_cmd` 解析逻辑匹配

## 5. 红外传感器的具体用法

当前代码**尚未接入红外**，但红外可在以下场景补强激光和视觉：

### 5.1 推荐安装位置


| 位置     | 数量建议  | 用途          |
| ------ | ----- | ----------- |
| 车头正前方  | 1     | 接近货架/平台边缘测距 |
| 车头左/右侧 | 1~2   | 侧向对位，防止擦碰   |
| 车尾     | 1（可选） | 倒车进区辅助      |


### 5.2 应用场景

#### 场景 A：取货区接近货架

- 流程：move_base 到达粗定位 → 视觉识别物资格子 → 底盘微调对位 → **红外检测货架距离 < 阈值则停止前进**
- 作用：防止撞货架，弥补激光在近距离/吸光表面的盲区

#### 场景 B：装货区 / 救援区平台对位

- 装货区平台：800×400×250mm，停机区 400×400mm
- 救援区放置区：100×100mm
- 红外检测平台立面前缘距离，配合 `go_linear_x/y` 做厘米级停车

#### 场景 C：辅助轮区判定

- 当 TF 精度不足时，红外检测车身与区域边界的距离
- 作为 `assert_wheels_in_zone` 的冗余校验

## 6. 无机械臂的机械替代方案

规则约束（V1.3 §6.1.1.1）：

- 加装模块自由度：**≤ 6（不包含夹爪）**
- 工作半径：≤ 700mm
- 车体（含加装模块）：长/宽/高 ≤ 800mm，重量 ≤ 35kg

以下方案均符合规则，且任务三允许"其他形式转移"。

### 6.1 方案 A：固定托盘 + 单舵机倾卸（推荐）

```
结构：车前/车顶固定 V 型托盘 + 1 个舵机控制倾卸角度
自由度：1 DOF（倾卸）
```

**流程**：

1. **取货**：视觉对位 → 慢速前进 → 圆柱滚入/被推入托盘
2. **运输**：托盘水平锁定
3. **装货**：到装货区对位 → 舵机倾卸 → 圆柱滑到无人机平台
4. **卸货**：到救援区 → 从无人机平台接收（或二次倾卸）→ 对准 100×100 放置区倾卸

**优点**：

- 结构简单，加工快
- 规则明确允许"其他形式转移"
- 可用现有 `/ep_pwm` 服务驱动舵机

**代码改造**：新建 `transfer_controller.py`，用 `RobotPwm` 替代 `ep_arm`/`ep_gripper`。

### 6.2 方案 B：前置固定夹爪 + 单舵机

```
结构：夹爪固定在车头，高度对准货架层，1 个舵机控制开合
自由度：1 DOF（夹爪）+ 底盘移动
```

**流程**：

1. 视觉识别格子 → 底盘对位（x, y, yaw）
2. 慢速前进至圆柱位于夹爪中心
3. 夹爪闭合抓取
4. 到装货区 → 张开夹爪释放到平台

**优点**：更符合"抓取"语义，任务二得分更稳。

**难点**：夹爪高度必须精确对准货架层（260mm 高，格子 160mm）；五个可取格子位置不同，可能需要不同前进距离表。

### 6.3 方案 C：推杆出料

```
结构：车内藏推杆，前进将圆柱从托盘推到平台
自由度：1 DOF（推杆伸缩）
```

适合装货区卸货，但取货仍需其他方式（铲入或手推测试阶段）。

### 6.4 方案 D：无人机从车顶取货

```
结构：车顶平台 + 限位槽
小车职责：运送到装货区并精确停位
无人机职责：降落取走圆柱
```

- 任务三得分依赖无人机抓取机构
- 小车侧主要得分在"精确对位"和区域进入
- 适合无人机能力强、小车机构弱的队伍

### 6.5 方案对比

### 7.5 `put_on_drone` 参考伪代码

```python
def put_on_drone(self):
    self._init_vision()
    transfer_cfg = self.config.get("transfer", {})

    # 1. 视觉/红外对位到无人机平台
    if not self._transfer.approach_platform("loading"):
        return False

    # 2. 确认驱动轮在装货区
    if not self.assert_wheels_in_zone("loading"):
        return False

    # 3. 执行倾卸
    if not self._transfer.tray_dump(
        angle=transfer_cfg.get("dump_angle", 45),
        hold_time=transfer_cfg.get("dump_hold", 1.5),
    ):
        return False

    # 4. 可选：摄像头确认平台上已有物资
    rospy.sleep(transfer_cfg.get("settle_time", 1.0))
    return True
```

### 7.6 `unload_to_target_zone` 参考伪代码

```python
def unload_to_target_zone(self):
    self._init_vision()
    transfer_cfg = self.config.get("transfer", {})

    # 1. 视觉识别 100×100 放置区（可用颜色胶带/标记）
    target = self._drop_detector.detect(self._camera.get_frame())
    if target is None:
        return False

    # 2. 底盘+红外精对位
    if not self._transfer.align_to_drop_zone(target):
        return False

    # 3. 倾卸/释放
    return self._transfer.tray_dump(
        angle=transfer_cfg.get("unload_angle", 50),
        hold_time=transfer_cfg.get("unload_hold", 2.0),
    )
```

## 10. 风险与注意事项

### 10.1 规则红线


| 风险            | 后果      |
| ------------- | ------- |
| 外部操控 / 外部电脑计算 | 违规，取消成绩 |
| 非任务性碰撞        | 每次 -5 分 |
| 停止超过 60 秒     | 本局结束    |
| 触碰围栏连续超过 30 秒 | 本局结束    |
| 冲出场地 / 失控     | 本局结束    |
| 120 秒内未启动     | 0 分     |
| 抓取不基于视觉       | 抓取不得分   |


### 10.2 技术风险


| 风险                   | 缓解措施                            |
| -------------------- | ------------------------------- |
| 赛场光照变化               | 两套 HSV 参数；或 YOLO 模型             |
| 定位漂移                 | 每次任务前重定位；关键区域红外修正               |
| SSH 断连               | 增加重试；考虑局域网 ping 预检              |
| 物资滚落                 | 托盘加挡边；倾卸角度分档测试                  |
| 无人机未及时 delivery_done | 增大 `timeouts.delivery`；无人机侧超时保护 |


### 10.3 高教组特别要求

- 加装模块须**自行设计**，不得直接使用未经实质性改装的成品
- 模块外立面及电路板须清晰呈现**校徽与队名**（3D 打印/激光雕刻/丝印）
- 需提交设备技术规格清单

### 10.4 职教组

- 允许基于成品结构改装
- 用时相同时，**自制设备**队伍排名靠前
